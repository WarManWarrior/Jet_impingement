# CFD Digital Twin - Project Documentation

## 1. Motivation and Approach
The goal of this project is to create an AI-powered **Digital Twin** that predicts 3D Computational Fluid Dynamics (CFD) fields (like Temperature, Pressure, and Velocity) instantly. Traditional CFD solvers (like Ansys Icepak) are computationally expensive and can take hours or days to evaluate a single design or operational configuration.

By using a **Physics-Informed 3D U-Net**, this approach completely bypasses the traditional governing equations (Navier-Stokes, energy equations) during inference. Instead, the AI learns the complex, non-linear mappings between input parameters (Inlet Velocity and Power) and the resulting 3D physics fields by training on a dataset of pre-solved simulations. 

This enables rapid, real-time exploration of the design space and instant operational feedback, providing outputs in milliseconds rather than hours.

## 2. Model Architecture (`digital_twin.py`)
The core of the Digital Twin is a **3D U-Net** (`CFDUnet3D`) built entirely in PyTorch. 

### Key Characteristics:
*   **Input Shape:** `(Batch, 3, 128, 128, 128)`
    *   Channel 0: Fluid Mask (1 for fluid, 0 for solid boundary/empty space).
    *   Channel 1: Input Velocity injected across the fluid mask.
    *   Channel 2: Input Power injected across the fluid mask.
*   **Output Shape:** `(Batch, 6, 128, 128, 128)`
    *   The model predicts 6 physics channels simultaneously: **Temperature, Pressure, Turbulent Kinetic Energy (TKE), Velocity X, Velocity Y, and Velocity Z**.
*   **Activation Functions:** Replaces standard ReLU with **GELU (Gaussian Error Linear Unit)**. Fluid dynamics have smooth, continuous gradients. ReLU introduces sharp mathematical cutoffs that lead to blocky, unphysical artifacting. GELU preserves the smooth physical nature of the flow fields.
*   **Skip Connections:** The U-Net encoder-decoder architecture pairs deep bottleneck representations (macro physics) with high-level skip connections to perfectly preserve sharp geometric boundaries and small-scale fluid phenomena.
*   **Physics Constraints:** The final output is multiplied by the input fluid mask. This perfectly enforces physical boundary conditions, guaranteeing that physics values (like velocity) inside solid walls drop precisely to 0.

## 3. Data Preprocessing Pipeline
Since raw CFD data exists as unstructured point clouds (millions of nodes), it must be transformed into structured tensor grids for the 3D CNN.

### Voxelization (`build_tensors.py` & `test_voxel_loss.py`)
*   **Resolution Selection:** The script `test_voxel_loss.py` systematically evaluates the Mean Absolute Error (MAE) and Root Mean Square Error (RMSE) introduced by binning continuous point clouds into discrete grids of varied resolutions (`64^3`, `128^3`, `192^3`, `256^3`). The chosen resolution of **128x128x128** acts as the sweet spot between structural fidelity and VRAM capacity.
*   **Mass Voxelization:** `build_tensors.py` automatically scans completed `.h5` CFD simulation results. It determines the universal physical bounding box, discretizes the space, and assigns Ansys node values to their corresponding voxels using robust spatial binning. A fluid mask is generated by identifying which voxels contain fluid nodes.
*   **Saving:** Preprocessed tensors are saved as highly compressed `.npz` files representing both the inputs (Mask, Velocity, Power) and targets (The 6 physics fields).

### Global Normalization (`get_global_bounds.py`)
Neural networks converge fastest when target variables are scaled to a `[0, 1]` range. `get_global_bounds.py` scans the entire processed dataset to find the exact absolute minimum and maximum values for every physics channel across *all* trials. This prevents data leakage and ensures scaling consistency.

## 4. Training and Validation (`train_twin.py` & `plot_loss.py`)
The training pipeline focuses on physics-specific convergence tracking and optimization. 

*   **DataLoader:** The custom `CFDTensorDataset` loads the `.npz` files, applies the pre-calculated global Min-Max scaling, and importantly, re-applies the fluid mask so empty space stays cleanly at 0.
*   **Objective Function:** **Smooth L1 Loss (Huber Loss)** is used. It acts like L1 (absolute error) when errors are small, and L2 (squared error) when errors are large, preventing exploding gradients from massive pressure fluctuations.
*   **Optimizer & Scheduler:** Employs **AdamW** (`lr=1e-4`, `weight_decay=1e-4`) in tandem with a `ReduceLROnPlateau` scheduler that halves the learning rate if the validation loss stagnates for 20 epochs. Mixed Precision (`torch.cuda.amp`) is used to accelerate training on the GPU.
*   **Deep Analysis:** Crucially, the validation loop breaks down the loss per physical component (Tracking Temperature, Pressure, and Velocity errors independently). This allows for deep visualization via `plot_loss.py`, guaranteeing that the model isn't just getting good at predicting pressure while failing at temperature.

## 5. Inference, Verification, and Export (`test_twin.py`)
Inference showcases the real value of the surrogate model.

*   **Zero-Shot Prediction:** `test_twin.py` allows the user to input specific untested boundaries (e.g., Velocity = `-7.5 m/s`, Power = `62.0 W`). The model utilizes a structural mask from the dataset as a geometry template.
*   **Inverse Scaling:** The raw `[0, 1]` predictions are mathematically inversed back to physical engineering units (`°C`, `Pa`, `m/s`).
*   **Engineering Metrics:** The script automatically calculates programmatic metrics like Max Chip Temperature, Temperature Rise (ΔT), and Estimated Thermal Resistance (°C/W).
*   **Matplotlib Presentation:** The script procedurally locates the exact Z-height of the hottest fluid, slices the 3D tensor horizontally, and creates high-quality 2D scientific colormap plots.
*   **VTK Export:** The raw 3D output arrays (including the reconstructed 3D Velocity vector field) are collapsed and saved as a `.vti` (VTK Image Data) file for professional exploration in ParaView or PyVista.

## 6. Interactive 3D Visualization (`interactive_viewer.py`)
The raw `.vti` file can be launched into a custom GPU-Accelerated 3D viewer built in PyVista. 
*   **Hardware Trace:** The script mathematically calculates hundreds of particle streamlines starting from the jet nozzle and sends them to the GPU.
*   **Rendering:** Uses hardware-accelerated shaders (`render_lines_as_tubes=True`) to render thick continuous flow plumes instantly. The application visualizes smooth and continuous aerodynamic interactions that were predicted entirely by the AI in under 10 milliseconds.
